# KPIs & Metrics Reference

> Auto-generated from `frontend/src/metrics.js` — do not edit directly.
> Regenerate with `node scripts/generate-docs.mjs` (or `make docs`).

This document defines every metric the system computes, its exact formula, and
why it matters for AI cost governance. It mirrors the code: raw telemetry lands
in `fact_observation` / `fact_score`, the calculation layer aggregates it into
**marts** (views in `warehouse/sql.py`), and the FastAPI layer exposes them as
**KPIs** (`api/kpis.py`).

| Layer | Where | What |
|---|---|---|
| Raw telemetry | `fact_observation` · `fact_score` | one row per observation / score |
| Marts (calculation) | `mrt_*` views in `warehouse/sql.py` | the derived grains |
| KPIs (serving) | `warehouse/base.py` + `api/kpis.py` | the JSON endpoints |

## 1. Raw telemetry

### `fact_observation` — one row per observation

| Column | Meaning |
|---|---|
| `input_tokens` | Tokens sent to the model (prompt + context). |
| `output_tokens` | Tokens generated by the model. |
| `total_tokens` | input_tokens + output_tokens. |
| `cached_input_tokens` | Input tokens served from a prompt cache (not re-prefilled). |
| `reasoning_tokens` | "Thinking" tokens on reasoning models (not visible output). |
| `total_cost` | Cost in USD (Langfuse model-price calculation). |
| `input_cost / output_cost` | Cost split by input / output. |
| `latency_ms` | end_time − start_time. |
| `session_id` | Groups multiple traces into one user/agent session. |
| `user_id · project_id · model · environment · trace_id` | Attribution dimensions. |

### `fact_score` — one row per eval result

| Column | Meaning |
|---|---|
| `trace_id / observation_id` | What was scored. |
| `name` | Eval name (e.g. correctness). |
| `value` | Numeric score (typically 0–1). |
| `source` | EVAL · ANNOTATION · API · … |

## 2. Marts — the calculation layer

### `mrt_daily_usage` — day × project × team × user × model

The workhorse grain — every "by dimension" KPI rolls up from it.

| Field | Formula |
|---|---|
| `observations` | COUNT(*) |
| `traces` | COUNT(DISTINCT trace_id) |
| `input / output / total tokens` | SUM(...) |
| `cached_input_tokens / reasoning_tokens` | SUM(...) |
| `total_cost` | SUM(total_cost) |
| `team` | joined from dim_user; "Unassigned" when unmapped |

### `mrt_model_efficiency` — per model

| Field | Formula |
|---|---|
| `cache_hit_rate` | SUM(cached_input_tokens) / SUM(input_tokens) |
| `reasoning_share` | SUM(reasoning_tokens) / SUM(total_tokens) |
| `output_input_ratio` | SUM(output_tokens) / SUM(input_tokens) |
| `cost_per_1k_tokens` | SUM(total_cost) × 1000 / SUM(total_tokens) |
| `avg_latency_ms` | AVG(latency_ms) |

### `mrt_session` — per session_id

The context-creep and cost-per-outcome signals.

| Field | Formula |
|---|---|
| `turns` | COUNT(DISTINCT trace_id) — model calls in the session |
| `observations` | COUNT(*) |
| `input / output / total tokens` | SUM(...) |
| `total_cost` | SUM(total_cost) |
| `first_seen / last_seen` | MIN / MAX(start_time) |

### `mrt_org_daily` — per day (whole org)

The cross-project org view Langfuse itself doesn’t provide.

| Field | Formula |
|---|---|
| `…` | same fields as mrt_daily_usage, rolled up to day |

### `mrt_model_daily` — day × model

Leading indicators (cache hit, reasoning, cost/1k, out:in) as a time series.

| Field | Formula |
|---|---|
| `cache_hit_rate` | SUM(cached_input_tokens) / SUM(input_tokens) |
| `reasoning_share` | SUM(reasoning_tokens) / SUM(total_tokens) |
| `output_input_ratio` | SUM(output_tokens) / SUM(input_tokens) |
| `cost_per_1k_tokens` | SUM(total_cost) × 1000 / SUM(total_tokens) |

### `mrt_hourly_usage` — hour × project

Intra-day cost/token grain for spike detection and heatmaps.

| Field | Formula |
|---|---|
| `observations` | COUNT(*) |
| `input / output / total tokens` | SUM(...) |
| `total_cost` | SUM(total_cost) |

### `mrt_governance_daily` — per day (latest canon snapshot)

Behaviour governance — proposals/ratifications over time.

| Field | Formula |
|---|---|
| `ttrp_ms` | time-to-first-ratified-policy (latest snapshot) |
| `precision14_ratio` | ratified ≤ 14d ÷ decided within window |
| `proposals_total / pending / ratified / rejected / decayed` | queue counts |

### `mrt_policy_coverage` — whole org (single row)

Share of traces covered by ratified policy evidence (upper bound — canon exports counts, not trace ids).

| Field | Formula |
|---|---|
| `ratified_policies` | COUNT(dim_policy) |
| `evidence_traces` | SUM(evidence_traces) |
| `total_traces` | COUNT(DISTINCT trace_id) |
| `coverage_ratio` | evidence_traces ÷ total_traces |

## 3. KPI catalog

### Cost

| KPI | Endpoint | Formula | Why it matters |
|---|---|---|---|
| **Cost (MTD)** | `/overview` | SUM(total_cost) since month start | The headline number; baseline for anomalies and budgets. |
| **Cost trend** | `/daily` | daily SUM(total_cost) by dimension | Where spend is growing or shrinking. |
| **Cost per 1k tokens** | `/overview` | SUM(total_cost) × 1000 / SUM(total_tokens) | Blended unit price; rises if you shift to pricier models or cache less. |
| **Cost per active developer** | `/overview` | cost_mtd / COUNT(DISTINCT user_id) | The Uber "$/engineer" number — normalizes cost by adoption. |
| **Cost per session** | `/overview · /sessions` | cost_mtd / COUNT(DISTINCT session_id) | Cost-per-outcome proxy — the "per-token is the wrong unit" fix. |
| **Budget burn rate** | `/governance` | cost_mtd / monthly_budget | Forecast and alert before overspend. |
| **WoW cost Δ** | `/overview` | (last_7d − prior_7d) / prior_7d × 100 | Week-over-week momentum. |
| **Cost anomalies** | `/anomalies` | cost[day] > threshold × mean(prior 14 days) | Spike detection vs a rolling baseline — catch runaway spend early. |

### Token efficiency

| KPI | Endpoint | Formula | Why it matters |
|---|---|---|---|
| **Output : Input ratio** | `/overview · /efficiency` | SUM(output_tokens) / SUM(input_tokens) | Context-bloat detector. A ratio collapsing toward 0 means you pay to re-read context with little output. |
| **Context per session** | `/sessions` | SUM(input_tokens) per session | The #1 agent cost driver — context grows ~linearly each turn and is re-sent every turn. |
| **Turns per session** | `/sessions` | COUNT(DISTINCT trace_id) per session | Agent-loop length; long loops × big context = cost explosion. |
| **Input per turn** | `/sessions` | SUM(input_tokens) / SUM(turns) | Context growth rate — the steepness of the context-creep curve. |
| **Cache hit rate** | `/overview · /efficiency` | SUM(cached_input_tokens) / SUM(input_tokens) | Prompt-caching savings; the single biggest immediate win for agentic workloads. |
| **Reasoning share** | `/efficiency` | SUM(reasoning_tokens) / SUM(total_tokens) | Overhead of "thinking" models; flag where reasoning is disproportionate. |
| **Tokens per task** | `/sessions` | total_tokens / turns | Unit token cost. |

### Governance

| KPI | Endpoint | Formula | Why it matters |
|---|---|---|---|
| **Unattributed spend** | `/governance` | SUM(total_cost) WHERE team = 'Unassigned' | Spend with no owner can’t be governed — surface it. |
| **Spend concentration** | `/governance` | top-5 users’ cost ÷ total cost (30d) | Who to coach/optimize first; risk concentration. |
| **Active users** | `/overview · /governance` | COUNT(DISTINCT user_id) | Adoption vs. cost sanity check. |
| **Top spenders** | `/top` | SUM(total_cost) by dimension, ordered | Attribution for operator/developer conversations. |

### Behaviour governance

| KPI | Endpoint | Formula | Why it matters |
|---|---|---|---|
| **Ratified policies** | `/behaviour` | COUNT(dim_policy) | The active canon — how much behaviour is pinned down as policy. |
| **Time to first policy (TTRP)** | `/behaviour` | first governance.promote − first connect | Time-to-value for the governance loop. |
| **Precision@14** | `/behaviour` | ratified ≤ 14d ÷ decided within window | Are proposals that get decided quickly ratified — signal quality of the queue. |
| **Proposal queue** | `/behaviour` | total / pending / ratified / rejected / decayed | The human-ratification backlog. |
| **Divergence by model × task** | `/behaviour` | divergent_traces ÷ total_traces per model × task-key | Where agents disagree on the same task — the raw material for policy. |

### Quality

| KPI | Endpoint | Formula | Why it matters |
|---|---|---|---|
| **Avg latency** | `/efficiency` | AVG(latency_ms) per model | Routing decisions; cheap ≠ fast. |
| **Pass rate** | `/quality` | passing ÷ scored, where MAX(value) ≥ threshold | Quality of what you’re paying for. |
| **Cost per successful outcome** | `/quality` | Σ cost(passing traces) ÷ count(passing) | The metric Uber lacked — cost tied to passing work. |
| **Cost per scored trace** | `/quality` | Σ cost(scored traces) ÷ count(scored) | Baseline cost per evaluable unit of work. |

### Time series & forecasting

| KPI | Endpoint | Formula | Why it matters |
|---|---|---|---|
| **Budget burn-down** | `/burndown` | cumulative cost vs budget; projected = cumulative + avg_daily × days_remaining | Will we blow the budget by month-end? |
| **Efficiency trend** | `/model-daily` | cache-hit / reasoning / cost-per-1k / out:in per day | Leading indicators — they move before cost does. |

## 4. Windows & conventions

- **MTD** (`/overview`, `/governance`): `start_time >= date_trunc('month', now())`.
- **Rolling window** (`/daily`, `/top`, `/sessions`, `/anomalies`): `day >= CURRENT_DATE − N days`
  (or `last_seen >= now() − N days` for sessions). Default `days=30`.
- **`team`** is `Unassigned` when `user_id` has no `dim_user` row or the team is empty —
  this is what feeds "unattributed spend".
- **Ratios are null-safe**: division by zero yields `null` (rendered as "—"), never an error.
- **Costs are USD** as computed by Langfuse's model pricing table.
